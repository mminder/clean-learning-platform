## Goal

GitHub Actions runs the backend and frontend checks on every pull request and on every push to `main`, so each later task gets automatic feedback.

## What to build

Read first: [D-30](../../decisions.md#architecture).

- **`.github/workflows/ci.yml`:**
  - triggers: `pull_request`, and `push` to `main`;
  - read-only `contents` permission;
  - a concurrency group that cancels superseded runs of the same pull request;
  - job **`backend`**: Temurin 25 with the Maven cache, then `./mvnw -B verify` in `backend/`. Testcontainers uses the runner's Docker;
  - job **`frontend`**: Node from `frontend/.nvmrc` with the npm cache, then `npm ci`, `npm run lint`, `npm run format:check`, `npm test` and `npm run build` in `frontend/`;
  - the current major versions of the official actions.
- Later tasks add their steps: `npm run check:api` ([06](06-shop-list.md)) and the jar build with the SPA ([08](08-spa-in-the-jar.md)).
- **Docs:** one line in AGENTS.md saying that CI runs the same commands as the **Commands** section.

## Acceptance criteria

- [x] This task's pull request shows the `backend` and `frontend` checks, and both are green (check them with the GitHub tools).
- [x] The workflow runs on pull requests and on pushes to `main`, not on every branch push.
- [x] A second push to the pull request cancels the run still in progress.
- [x] The second run hits the Maven and npm caches.

## Tests

None. The workflow is checked by its own run on this task's pull request.

## Out of scope

- Deployment, container images, release builds: MVP.
